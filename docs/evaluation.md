# Evaluation Methodology

## Overview

GraphProbe AI evaluates RAG, GraphRAG, and Agentic GraphRAG pipelines using a comprehensive metrics framework designed to answer the central research question:

**"When does Agentic GraphRAG actually provide enough additional reasoning value to justify its additional retrieval steps, latency, and token cost?"**

## Metrics

### Accuracy Metrics

#### Correctness
- **Definition**: Number of questions meeting correctness criteria / total evaluated questions
- **Calculation**: Binary classification based on ground truth comparison
- **Evaluation**: LLM-as-judge or manual review for visible dataset

#### Completeness
- **Definition**: Required answer facts supported / expected answer facts
- **Calculation**: Fact-level comparison between generated answer and ground truth
- **Evaluation**: Structured fact extraction and comparison

### Evidence Metrics

#### Citation Coverage
- **Definition**: Supported claims with valid citations / claims requiring evidence
- **Calculation**: Claim-level citation validation
- **Evaluation**: Automatic citation grounding check

#### Evidence Quality
- **Source relevance**: Relevance score of retrieved evidence
- **Evidence coverage**: Percentage of answer supported by evidence
- **Entity coverage**: Percentage of key entities supported
- **Relationship coverage**: Percentage of key relationships supported

### Efficiency Metrics

#### Token Efficiency
- **Input tokens**: Tokens sent to LLM
- **Output tokens**: Tokens generated by LLM
- **Total tokens**: Sum of input and output
- **Tokens per successful answer**: Total tokens / correct answers

#### Retrieval Efficiency
- **Retrieval steps**: Number of retrieval operations
- **Chunks retrieved**: Number of document chunks
- **Graph nodes**: Number of graph nodes visited
- **Graph edges**: Number of graph edges traversed
- **Tools used**: List of tools invoked (for agentic)

### Performance Metrics

#### Latency
- **Retrieval latency**: Time for retrieval operations
- **Generation latency**: Time for LLM generation
- **Total latency**: End-to-end time
- **Per-step latency**: Average time per retrieval step

### Agentic Behavior Metrics

#### Iterations
- **Total iterations**: Number of agent loops
- **Strategy changes**: Number of times agent changed approach
- **Tool selection**: Distribution of tools used
- **Stopping reason**: Why agent stopped (evidence, budget, max iterations)

## Evaluation Pipeline

### Step 1: Benchmark Execution
```bash
python scripts/benchmark.py --questions evaluation/datasets/questions_visible.json
```

This runs all three pipelines on each question and captures:
- Answers and citations
- Evidence and graph context
- Metrics (latency, tokens, retrieval)
- Agent traces (for agentic)

### Step 2: Result Evaluation
```bash
python scripts/evaluate.py <run_id>
```

This calculates:
- Accuracy and completeness scores
- Citation coverage
- Aggregate metrics per pipeline
- Question classification

### Step 3: Report Generation
The evaluation generates:
- Per-question results (JSON)
- Aggregate metrics (JSON)
- Classification summary (JSON)
- Dashboard-ready data (JSON)

## Question Classification

After evaluation, questions are classified based on measured behavior:

### RAG Sufficient
- **Criteria**: RAG achieves ≥80% accuracy with minimal latency
- **Characteristics**: Simple factual questions, direct document lookup
- **Interpretation**: Agentic investigation not justified

### GraphRAG Useful
- **Criteria**: GraphRAG outperforms RAG by ≥10% accuracy
- **Characteristics**: Questions requiring entity relationships, structural reasoning
- **Interpretation**: Graph structure provides value over vector similarity

### Agentic Investigation Useful
- **Criteria**: Agentic outperforms both RAG and GraphRAG by ≥10% accuracy
- **Characteristics**: Multi-hop questions, evidence gaps, need for adaptive retrieval
- **Interpretation**: Additional investigation cost justified by accuracy gain

## Fair Comparison

All three pipelines receive:
- Same question
- Same corpus
- Comparable model configuration
- Same evaluation method
- Documented differences (e.g., graph traversal vs vector search)

## LLM-as-Judge

When using LLM for evaluation:

### Judge Prompt
```
You are an impartial evaluator of RAG system answers.

Question: {question}
Generated Answer: {answer}
Ground Truth: {ground_truth}

Evaluate:
1. Correctness: Is the answer factually correct? (yes/no/partial)
2. Completeness: Does it cover all required facts? (percentage)
3. Evidence: Is it well-supported by citations? (yes/no/partial)

Provide scores and reasoning.
```

### Validation
- Save judge outputs
- Save criteria used
- Clearly label as LLM-generated evaluation
- Provide option for manual review

## Limitations

- Ground truth quality affects accuracy evaluation
- LLM-as-judge may have biases
- Citation extraction is heuristic
- Evidence sufficiency is estimated, not ground truth
- Classification thresholds are configurable
